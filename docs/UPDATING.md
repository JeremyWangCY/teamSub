# 应用更新

在「设置 → 更新」点击检查，再点击「下载并更新」。界面显示百分比、已下载大小及取消按钮。下载完成后先保存会议和取消尚未完成的补译，随后退出、安装到原目录并重新启动。关闭更新页面不会丢失下载进度，重新进入可继续查看。主窗口关闭仍收进托盘；退出操作才结束进程。

0.1.12 及更早版本没有这套自动安装流程，首次升级需要下载新版安装包，从托盘退出旧版后覆盖安装。源码运行保留手动下载入口。

## 校验与隐私

只接受本项目正式 Release 的精确版本安装包。通过 GitHub HTTPS 元数据取得文件大小及 SHA256，下载可跟随 GitHub 官方资源域名；临时文件完整校验大小、文件头和摘要后才可安装。没有可信摘要的旧 Release 仅提供手动下载。安装前再次校验安装包及旧程序备份。校验能发现下载损坏和文件被修改，不能替代代码签名或防范仓库发布权限被入侵。

更新功能不读取翻译密钥、服务配置或会议内容，不带 GitHub 登录凭据。它保留系统代理设置；网络受限时可重试或选择手动下载。连接和单次读取有超时，取消在读取边界生效。

## 保存与恢复

- 下载失败、取消、校验失败：清除未完成的临时下载，旧程序继续运行。
- 磁盘空间、目录权限或备份校验失败：不退出，不启动安装器，显示实际错误。
- 更新前有未保存的编辑：先由现有草稿保护流程处理；保存失败时停止更新并恢复采集。
- 安装启动失败：保留窗口、恢复会议写入线程和采集，可继续记录并重试。
- 安装器只在记录线程完成关闭后启动，等待旧应用及其单文件父进程退出；超时则不覆盖文件，不强制结束旧程序。
- 安装失败或安装器无法创建新版进程：尝试从下载目录中经过 SHA256 核验的 `TeamsSub.previous.exe` 恢复旧程序并启动。配置和会议目录不在安装覆盖清单中。进程创建成功后发生的应用崩溃不在此自动判定范围内。

断电、杀死安装器、磁盘损坏或恢复文件持续被占用时，不能保证自动恢复成功。保留下载目录中的备份和 `install.log`，从可信 Release 手动重装到原目录；不要删除 `appconfig.json` 和 `captions/`。备份及日志留在 `cache/updates/`，确认版本稳定后可自行删除该版本缓存。

## 验证范围

自动安装、等待父子进程、超时保留、错误备份拒绝，以及文件写入失败和新版无法启动的恢复路径使用独立应用标识与 .NET 测试程序验证。正式 TeamsSub 二进制另行检查安装、覆盖升级、卸载及内嵌依赖；两类证据不混称。真实 Windows 系统和账户覆盖范围见 [兼容性说明](COMPATIBILITY.md)。
